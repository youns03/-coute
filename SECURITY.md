# Security policy

## Reporting a vulnerability

Please do not report exploitable vulnerabilities in a public issue.

Use GitHub's **Private vulnerability reporting** feature for this repository when it is enabled. If it is unavailable, contact the repository owner privately through a verified GitHub contact method and include:

- A concise description of the issue and its impact.
- Affected commit, release, Android version, and device/ABI if relevant.
- Minimal reproduction steps or a proof of concept that does not expose real user data.
- Any suggested mitigation.

Please allow reasonable time for investigation and a fix before public disclosure.

## Sensitive data

Do not publish any of the following in issues, pull requests, logs, or commits:

- Release keystores, passwords, signing aliases, or API credentials.
- Private books, documents, transcripts, or audio recordings.
- Personal information or local configuration files.
- Downloaded model packages unless their redistribution terms explicitly allow it.

## Scope

Security reports are welcome for the Android application, model download and verification flows, document processing, local storage, and GitHub Actions workflows.
